# Конспект
## Про Make и автоматизацию сборки

Программа `make` - это мощный инструмент для автоматизации сборки программ из исходного кода. Она помогает компилировать только те файлы, которые были изменены, что сильно экономит время при работе над большими проектами.

### Общая структура `Makefile`

`Makefile` состоит из **правил**. Каждое правило описывает, как получить **целевой файл (target)** из **файлов-зависимостеДобавить конспект по Make и системным вызовамй (prerequisites)**.

**Синтаксис правила:**

```
target: prerequisites
	command
```

- `target` - файл, который нужно создать (например, исполняемый файл).
- `prerequisites` - файлы, которые нужны для создания `target`.
- `command` - команда, которая будет выполнена. Перед командой обязательно должен стоять **символ табуляции**.

### `Makefile` с лекции

Цель - автоматизировать сборку всех `.c` файлов.

```make
SRCS = $(wildcard *.c)
PROGS = $(patsubst %.c,%.elf,$(SRCS))

all: $(PROGS)

%.elf: %.c
	$(CC) $(CFLAGS)  -o $@ $<

clean:
	rm -f *.elf
```

- `SRCS = $(wildcard *.c)`: Эта строка находит **все файлы, заканчивающиеся на `.c`**, в текущей папке и сохраняет их имена в переменной `SRCS`.
- `PROGS = $(patsubst %.c,%.elf,$(SRCS))`: Эта строка преобразует имена файлов из переменной `SRCS`. Например, `main.c` станет `main.elf`.
- `all: $(PROGS)`: Эта цель по умолчанию. Запуск `make` без аргументов будет компилировать все `.c` файлы.
- `%.elf: %.c`: Это шаблонное правило. `make` будет использовать его для создания любого `.elf` файла из соответствующего `.c` файла.
- `$@` и `$<`: Это автоматические переменные. `$@` подставляет имя целевого файла, а `$<` - имя первого файла-зависимости.

> [!tip]
> `Makefile`  работает автоматически, даже если мы добавляем новые файлы с кодом.

### ELF (Executable and Linkable Format)

**ELF** - это стандартный формат исполняемых файлов, объектных файлов и библиотек, используемый в Linux и других UNIX-подобных операционных системах. Это своего рода «контейнер» для кода и данных программы.

### `objdump` и дизассемблирование

`objdump` - это утилита, которая отображает информацию из объектных файлов. С помощью флага `-d` она выполняет **дизассемблирование** (преобразование машинного кода в ассемблерные инструкции).

**Пример:** `objdump -d my_program.elf`

### 64-bit vs. 32-bit архитектуры

Разница в размере **машинного слова**, которое процессор может обработать за раз.

- **32-битная:** Максимальный объем ОЗУ около 4 ГБ.
- **64-битная:** Может адресовать гораздо больший объем ОЗУ, что позволяет работать с более сложными приложениями.

> [!warning]
Ограничение в 4 ГБ в 32-битной архитектуре возникает из-за размера адреса. 32-битный адрес позволяет адресовать 2^32 байт, что равно 4 ГБ.

**Схема адресации:**

```
+----------------+  +----------------+
|  32-битная     |  |  64-битная     |
|  архитектура   |  |  архитектура   |
+----------------+  +----------------+
| Адрес (32 бита)|  | Адрес (64 бита)|
+----------------+  +----------------+
| 0...0   = 0 ГБ |  | 0...0  = 0 ГБ  |
| ...            |  | ...            |
| 1...1   = 4 ГБ |  | 1...1  = 16 ЭБ |
+----------------+  +----------------+
```

## Функции C vs. Системные вызовы

Очень важно понимать разницу между функциями из стандартной библиотеки C и системными вызовами, которые обращаются напрямую к ядру ОС.

### Что такое системный вызов (Syscall)?

**Системный вызов** (syscall) - это запрос, который программа отправляет ядру операционной системы для выполнения какой-либо операции, требующей привилегий, например, работы с файлами, сетью или памятью. Это «дверь» между программой в режиме пользователя и ядром в режиме ядра.

### Почему системные вызовы - «дорогая» операция?

Системный вызов требует **переключения контекста процессора**, что занимает много времени.

**Процесс системного вызова:**

1. **Вызов:** Программа переходит в режим ядра.    
2. **Сохранение контекста:** Процессор сохраняет текущее состояние программы (регистры, указатель на инструкцию и т.д.).
3. **Переход в ядро:** Управление передается ядру.
4. **Выполнение:** Ядро выполняет запрошенное действие.
5. **Восстановление контекста:** Ядро восстанавливает сохраненное состояние программы.
6. **Возврат:** Управление возвращается программе.

Эта смена контекста занимает много времени, поэтому системные вызовы нужно использовать пореже.

### Буферизация как способ минимизации системных вызовов

**Буферизация** - это техника, при которой данные сначала накапливаются во временной области памяти (буфере), а затем записываются в целевой файл или выводятся на экран одним большим блоком, а не по одному байту. Это позволяет значительно сократить количество медленных системных вызовов `write`.

### `exit()` vs. `_exit()`: Пример `atexit.c`

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

void bye() {
    printf("\nBye!\n");
}

void f1() {
    printf("hello from main");
    exit(0);
}

void f2() {
    printf("hello from main");
    _exit(0);
}

void f3() {
    printf("hello from main\n");
    _exit(0);
}

int main() {
    atexit(bye);
    // f1();
    // f2();
    f3();
}
```

- `atexit(bye)`: Регистрирует функцию `bye()` для вызова перед нормальным завершением.
- `f1()` вызывает `exit(0)`, которая выполняет очистку, вызывает `atexit` функции и только потом делает системный вызов `_exit()`.
- `f2()` и `f3()` вызывают прямой системный вызов `_exit(0)`. Он завершает программу немедленно, **не вызывая `atexit` функции** и **не сбрасывая буферы**. В `f3()` текст выводится, потому что `\n` принудительно сбрасывает буфер.

> [!warning]
Используя `_exit()`, мы можем потерять данные из буферов, так как очистка не выполняется!

### Замер времени: Пример `syscall_time.c`

Пример, показывающий, как количество системных вызовов влияет на производительность

```c
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <time.h>

void print_space(size_t repeats) {
    for (size_t i = 0; i < repeats; ++i) {
        printf("%lu - Hello world ", i);
    }
}

void print_new_line(size_t repeats) {
    for (size_t i = 0; i < repeats; ++i) {
        printf("%lu - Hello world\n", i);
    }
}

int main(int argc, char** argv) {
    if (argc != 2) {
        printf("Usage: %s <integer>\n", argv[0]);
        return 1;
    }

    int repeats = atoi(argv[1]);

    clock_t space_time = clock();
    print_space(repeats);
    space_time = clock() - space_time;
    double space_time_taken = ((double)space_time) / CLOCKS_PER_SEC;

    clock_t new_line_time = clock();
    print_new_line(repeats);
    new_line_time = clock() - new_line_time;
    double new_line_time_taken = ((double)new_line_time) / CLOCKS_PER_SEC;

    printf("\nSpace time:\t%f sec\nNew Line time:\t%f sec\n", space_time_taken,
           new_line_time_taken);
}
```

- **`print_space`**: Выводит текст без перевода строки. Вся строка будет выведена за **один или несколько системных вызовов `write`** после завершения цикла. Это гораздо быстрее.
- **`print_new_line`**: Выводит текст с переводом строки (`\n`). Стандартная библиотека C сбрасывает буфер при каждом переводе строки, поэтому каждый `printf` делает **отдельный системный вызов `write`**. Это намного медленнее.

### `strace` - отслеживание системных вызовов

`strace` - утилита, которая отслеживает системные вызовы, выполняемые процессом. Это отличный способ увидеть, что делает твоя программа.

**Пример:** `strace -e write ./syscall_time.elf 2`

## Работа с файлами в Linux
### Что такое файловый дескриптор?

**Файловый дескриптор** - это уникальное неотрицательное целое число, которое ядро операционной системы выделяет для доступа к файлу, каналу, сокету или другому ресурсу ввода-вывода. Это абстрактный указатель на ресурс.

- `0` - `STDIN_FILENO` (стандартный ввод, клавиатура).
- `1` - `STDOUT_FILENO` (стандартный вывод, экран).
- `2` - `STDERR_FILENO` (стандартный вывод ошибок, экран).

```c
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <unistd.h>

enum { BUF_SIZE = 8 };

int main(int argc, char* argv[]) {
    if (argc < 2) {
        fprintf(stderr, "expected filename\n");
        exit(1);
    }

    int fd =
        open(argv[1],
             O_WRONLY /*пишем*/ | O_CREAT /*создаем*/ | O_APPEND /*дописываем*/,
             S_IRUSR | S_IWUSR);

    if (fd < 0) {
        fprintf(stderr, "failed open file\n");
        exit(1);
    }

    char buf[BUF_SIZE];
    ssize_t input_size;

    while ((input_size = read(STDIN_FILENO, buf, BUF_SIZE)) > 0) {
        if (input_size < 0) {
            fprintf(stderr, "failed read\n");
            exit(1);
        }

        ssize_t output_size = write(fd, buf, input_size);
        if (output_size != input_size) {
            fprintf(stderr, "failed write\n");
            exit(1);
        }
    }

    int close_res = close(fd);
    if (close_res == -1) {
        fprintf(stderr, "failed write\n");
        exit(1);
    }

    return 0;
}
```

- **`open()`**: Открывает или создает файл, возвращает файловый дескриптор.
- **`read()`**: Считывает данные из дескриптора в буфер.
- **`write()`**: Записывает данные из буфера в дескриптор.
- **`close()`**: Закрывает файловый дескриптор, освобождая ресурс ОС.

>[!tip] 
Как `read()`, так и `write()` могут считать/записать меньше байтов, чем ты запросил. Поэтому в коде, который работает с большими файлами, их всегда используют в цикле, чтобы гарантировать полную обработку данных.

## Командная строка: `Ctrl+D`

`Ctrl+D` в командной строке посылает сигнал, который означает **конец ввода (End of File)**. Программа получает 0 байт на чтение, что говорит ей, что ввод завершен.
