# Конспект

## 1. Директория `/proc/`

- `/proc/` - это виртуальная файловая система, предоставляемая ядром Linux.
- Она содержит информацию о текущих процессах и состоянии системы:
    - `/proc/<pid>` - каталог с информацией о конкретном процессе.
    - `/proc/meminfo` - данные о памяти.
    - `/proc/cpuinfo` - данные о процессоре.

Используется как механизм отладки и мониторинга.

---

## 2. Работа с процессами: `ps -u user | grep`

- `ps -u user` - выводит список процессов, запущенных пользователем.
- `grep` позволяет фильтровать этот список по имени процесса или другому критерию.  
    Пример:

```bash
ps -u ivan | grep firefox
```

Выводит все процессы пользователя _ivan_, связанные с Firefox.

## 3. Управление памятью: heap, `sys_brk`, `mmap`, `malloc`

### Системные вызовы

- **`sys_brk`** - изменяет конец кучи (heap). Исторически использовался для выделения памяти программам.
- **`mmap`** - отображает файлы или анонимные области памяти в адресное пространство процесса. Современные `malloc` используют именно `mmap` для больших блоков памяти.

### Как работает `malloc`

- Под капотом `malloc` управляет кучей.
- Для выделения памяти оно использует:
    - **`brk`** - для небольших запросов.
    - **`mmap`** - для крупных запросов.
- Реализация может быть основана на односвязном списке свободных блоков.

Примерная схема:

```c
struct block {
    size_t size;
    struct block* next;
};

void* my_malloc(size_t size) {
    // ищем подходящий свободный блок или расширяем кучу
}
```

## 4. Потоки vs процессы

### Процессы

- У каждого процесса **свое виртуальное адресное пространство**.
- Если один процесс падает, другие не страдают.
- **Плюсы:**
    - Изоляция.
    - Повышенная надежность.
- **Минусы:**
    - Большие накладные расходы на создание.
    - Сложнее обмениваться данными.
    
### Потоки

- Потоки одного процесса **делят общее адресное пространство**.
- **Плюсы:**
    - Более быстрый старт.
    - Удобный доступ к общей памяти.
- **Минусы:**
    - Ошибка в одном потоке может «повалить» весь процесс.

## 5. Системный вызов `fork` и идиома fork-join

### Что делает `fork`

- Создает новый процесс (дочерний), являющийся копией родительского.
- В родительском процессе `fork` возвращает **PID дочернего процесса**.
- В дочернем - `0`.

### Примеры использования

- **Shell** использует `fork`, чтобы запускать команды.
- **Web-серверы** (например, Apache) создают отдельные процессы для обработки запросов.
- **Браузеры** (Chrome) используют процессы для вкладок, чтобы изоляция защищала остальные вкладки при сбое.

### Примеры программ

1. **01-fork-simple.c**  

```c
#include <stdio.h>
#include <unistd.h>

int main(void) {
    puts("hello");
    fork();
    puts("bye");
    return 0;
}
```

Почему `bye` выводится дважды? Потому что есть два процесса: родитель и ребенок.

2. **02-fork-join.c** 

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main(void) {
    int x, wstatus;
    puts("parent only");

    x = fork();
    if (x > 0) {
        printf("parent: do half task \n");
        wait(&wstatus);
        if (WIFEXITED(wstatus)) {
            printf("exited, status=%d\n", WEXITSTATUS(wstatus));
        } else if (WIFSIGNALED(wstatus)) {
           printf("killed by signal %d\n", WTERMSIG(wstatus));
        }

    } else {
        printf("child: do half task \n");
        int ret = 3; // half task result
        sleep(10);
        exit(ret);
    }
    puts("parent only");

    return 0;
}
```

Разделяем задачу (например, поиск максимума в массиве) между двумя процессами. Родитель ждет завершения дочернего через `wait`.

3. **03-fork-memory.c**  

```c
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

void main(void) {
    int pid, status;
    int arr[100000] = {1, 2, 3};
    pid = fork();
    if (pid > 0) {
        arr[1] = 200;
        wait(&status);
    } else {
        sleep(3);
        printf("child: arr[1]=%d \n", arr[1]);
        exit(0);
    }
}
```

Дочерний процесс получает копию памяти родителя.

## 6. Copy-on-Write (COW)

- При `fork` ядро **не копирует все страницы памяти**, а лишь создает новые таблицы отображения.
- Физически родитель и ребенок используют одни и те же страницы в режиме только для чтения.
- При попытке записи возникает **page fault**:
    - Ядро создает копию страницы.
    - Обновляет таблицу страниц для процесса.
    - Повторяет инструкцию записи.

Пример 1:

```c
x = fork();
if (x > 0) {
    arr[1] = 200; // вызовет page fault и копирование страницы
    arr[2] = 300; // уже нормальная запись без page fault
}
```

Пример 2 (с практики):

```c
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

static __inline__ unsigned long long rdtsc(void) {
    unsigned hi, lo;
    __asm__ __volatile__("rdtsc" : "=a"(lo), "=d"(hi));
    return ((unsigned long long)lo) | (((unsigned long long)hi) << 32);
}

int arr[10000000] = {0};

void main(void) {
    int pid, status;
    long long t1, t2, t3, t4;
    pid = fork();
    if (pid > 0) {
        t1 = rdtsc();
        arr[10000] = 20;
        t2 = rdtsc();
        arr[10010] = 30;
        t3 = rdtsc();
        arr[10020] = 40;
        t4 = rdtsc();

        printf("t2 - t1 = %lld\n", t2 - t1);
        printf("t3 - t2 = %lld\n", t3 - t2);
        printf("t4 - t3 = %lld\n", t4 - t3);
        wait(&status);
    } else {
        printf("child \n");
        exit(0);
    }
    puts("parent only");
}
```

## 7. Работа с файлами при `fork`

- Копии **объектов ядра, описывающих файлы** не создаются.
- Родитель и ребенок имеют общие файловые дескрипторы.
- Например, текущая позиция в файле будет общей.

```c
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

void main(void) {
    int pid, status, fd;
    fd = open("./notes.md", O_RDWR);
    pid = fork();
    if (pid > 0) {
        char buf[31];
        read(fd, buf, 30);
        buf[30] = 0;
        puts(buf);
        wait(&status);
    } else {
        char buf[31];
        //sleep(3);
        read(fd, buf, 30);
        buf[30] = 0;
        puts(buf);
        exit(0);
    }
}
```

## 8. Пример с массивом задач и `prctl`

```c
#include <stdlib.h>
#include <sys/prctl.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

#include "stdio.h"

void task1(void) {
    prctl(PR_SET_NAME, "task1");
    while (1) {
        puts("task1");
        sleep(10);
    }
}

void task2(void) {
    prctl(PR_SET_NAME, "task2");
    while (1) {
        puts("task2");
        sleep(10);
    }
}

void task3(void) {
    prctl(PR_SET_NAME, "task3");
    while (1) {
        puts("task3");
        sleep(10);
    }
}

void task4(void) {
    prctl(PR_SET_NAME, "task4");
    while (1) {
        puts("task4");
        sleep(10);
    }
}

void task5(void) {
    int c = 0;
    prctl(PR_SET_NAME, "task5");
    while (1) {
        c++;
        if (c == 5) exit(12);
        puts("task5");
        sleep(3);
    }
}

void (*arr[5])(void) = {task1, task2, task3, task4, task5};

int findpid(int *arr, int size, int val) {
    int i;
    for (i = 0; i < size; i++) {
        if (arr[i] == val) return i;
    }
    return -1;
}

int main(void) {
    int ids[5];
    int v, i, status, pid, pos;
    for (i = 0; i < 5; i++) {
        v = fork();
        if (v == 0) {
            arr[i]();
            exit(0);
        }
        ids[i] = v;
    }
    while (1) {
        pid = wait(&status);
        pos = findpid(ids, 5, pid);
        printf("bye сhild %d %d\n", pid, status);
        printf("Child exits with status of %d\n", WEXITSTATUS(status));
        v = fork();
        if (v == 0) {
            arr[pos]();
            exit(0);
        }
        ids[pos] = v;
    }
    return EXIT_SUCCESS;
}
```

* если один процесс упадет, то остальные не пострадают
* создается 5 задач (рулить марсоходом, вертеть солнечной батареей, поддерживать контакт с хьюстоном) и управляющий процесс
* если он из задач упала (имитируем с помощью kill или exit в task5), то управляющий процесс ее перезапустит

## 9. `execlp`

- Системный вызов `execlp` заменяет текущий процесс новым исполняемым файлом (запускает программу, ищет её в `PATH`).
- В отличие от `fork`, процесс не дублируется, а «переписывается» новым содержимым.
- Применяется в комбинации с `fork`:
    - `fork` создает новый процесс.
    - `execlp` в дочернем процессе запускает нужную программу.

### Пример использования execlp:

```c
#include <unistd.h>
#include <stdio.h>

int main() {
	pid_t pid = fork();
	
	if (pid == 0) {
		// Дочерний процесс заменяет себя программой ls
		execlp("ls", "ls", "-l", "-a", NULL);
		// Если exec вернётся, значит произошла ошибка
		perror("execlp failed");
	} else {
		// Родитель ждёт
		wait(NULL);
		printf("Child finished.\n");
	}
	
	return 0;
}
```

При запуске программа вызовет `ls -l -a`. Дочерний процесс полностью заменит свой код на `ls`.
