# Конспект

### Что такое текстовый файл?

Текстовый файл – это простой файл, который хранит данные в виде последовательности символов. Он состоит из байтов, где каждый байт (или несколько байтов) представляет собой определённый символ, согласно какой-либо кодировке (например, ASCII или UTF-8).

#### Как данные хранятся на жёстком диске?

Данные на жёстком диске хранятся на физическом уровне в виде магнитных полей, которые организованы в **дорожки** и **секторы**. На логическом уровне операционная система работает с **блоками** (clusters).

**Файловая система** (например, NTFS, ext4) управляет этим. У каждого файла есть своя структура данных, которая называется **inode** (индексный дескриптор). `inode` не хранит сам файл, а содержит **метаданные** о нём:

- Размер файла
- Владелец и группа
- Права доступа (permissions)
- Временные метки (создание, изменение)
- Указатели на блоки данных, где физически находится файл на диске.

Когда ты открываешь файл, файловая система использует `inode`, чтобы найти нужные блоки на диске, собрать их в правильном порядке и передать программе для чтения.

### Little-endian и Big-endian

Это два способа записи байтов многобайтового числа в памяти или на диске.

- **Little-endian:** младший (наименее значимый) байт записывается первым. Это наиболее распространенный порядок в современных процессорах (например, x86).
- **Big-endian:** старший (наиболее значимый) байт записывается первым. Этот порядок используется в сетевых протоколах и некоторых процессорах (например, PowerPC).

**Пример:** число `0x12345678` (шестнадцатеричное).

- В **Big-endian** оно будет храниться как: `12 34 56 78`
- В **Little-endian** оно будет храниться как: `78 56 34 12`

#### Как работает `hexdump`?

Команда `hexdump` показывает содержимое файла в шестнадцатеричном виде. Если ты запустишь `hexdump` на файле, содержащем многобайтовые числа, ты увидишь их в порядке, который соответствует **endianness** архитектуры компьютера.

### Bash и перенаправление потоков

В Unix-подобных системах у каждого процесса есть три стандартных потока ввода-вывода, представленные **файловыми дескрипторами (file descriptors)**:

- `0` – **stdin** (стандартный ввод)
- `1` – **stdout** (стандартный вывод)
- `2` – **stderr** (стандартный вывод ошибок)

#### Как работает `echo` с перенаправлением (`>` и `>>`)?

Когда ты вводишь команду `echo "Hello World!" > hello.txt`, происходит следующее:

1. **Вызов `fork`:** Bash создает точную копию своего процесса, который теперь является дочерним.
2. **Перенаправление:** В дочернем процессе Bash перенаправляет файловый дескриптор `1` (стандартный вывод) на новый файл `hello.txt`. Это означает, что всё, что будет записано в `1`, попадёт в `hello.txt`.
3. **Вызов `exec`:** Дочерний процесс замещается командой `echo`.
4. **Запись:** Команда `echo` выполняет системный вызов `write`, записывая "Hello World!" в свой стандартный вывод (`1`).
5. **Операционная система** направляет эту запись в `hello.txt` благодаря перенаправлению, установленному на шаге 2.

**Разница между `>` и `>>`:**

- `>` перезаписывает содержимое файла.
- `>>` добавляет данные в конец файла, сохраняя старое содержимое.

#### Как помогает `dup2`?

`dup2` – это системный вызов, который копирует один файловый дескриптор на другой. Это позволяет реализовать перенаправление на низком уровне.

```c
int fd = open("hello.txt");
dup2(fd, 1); // Файловый дескриптор 1 (stdout) теперь указывает на "hello.txt"
close(fd);  // fd больше не нужен

// Когда программа вызывает write(1, ...), она пишет в "hello.txt"
write(1, "Hello World!", 13);
```

Схема с пары:

```bash
kernel
file {
    size_t blocks[1000];
} f;

fd --> f
1 --> f
```

`dup2(fd, 1)` заставляет `1` указывать на ту же структуру файла в ядре, что и `fd`.

### Как работает `chmod`?

`chmod` (change mode) меняет права доступа к файлу или директории. Права доступа делятся на три категории:

- **User (u):** владелец файла.
- **Group (g):** группа, которой принадлежит файл.
- **Others (o):** все остальные.

Для каждой категории можно установить три права:

- **r (read, чтение):** `4` в восьмеричной системе.
- **w (write, запись):** `2` в восьмеричной системе.
- **x (execute, выполнение):** `1` в восьмеричной системе.

Общая сумма прав доступа для каждой категории представлена одной цифрой.

- `rwx` (7): `4 + 2 + 1`
- `r-x` (5): `4 + 0 + 1`
- `rw-` (6): `4 + 2 + 0`
    

**Пример:** `chmod 755 script.sh`

- `7`: права владельца (`rwx`).
- `5`: права группы (`r-x`).
- `5`: права остальных (`r-x`).

### Перенаправление `1>`, `2>`, `2>&1`

- `1>`: Явное перенаправление стандартного вывода (stdout).
    - `ls > files.txt` – это то же самое, что `ls 1> files.txt`.
- `2>`: Перенаправление стандартного вывода ошибок (stderr).
    - `./my_program 2> errors.log` – записывает все ошибки в файл `errors.log`.
- `2>&1`: Перенаправление стандартного вывода ошибок (`2`) в то же место, что и стандартный вывод (`1`). Символ `&` используется для указания, что `1` – это файловый дескриптор, а не имя файла.
    - `ls -l /tmp /non_existent_dir > all.log 2>&1` – все, и успешный вывод, и ошибки, будут записаны в один файл `all.log`.

### Как работают `pipe` и `pipe2`?

`pipe` (труба) – это механизм межпроцессного взаимодействия (IPC), который позволяет соединить стандартный вывод одной программы со стандартным вводом другой.

**Пример из Bash:** `ls -l | less`

1. Bash вызывает `pipe()`, который создает два файловых дескриптора: один для чтения (`r_fd`) и один для записи (`w_fd`).
2. Bash вызывает `fork()` дважды, создавая два дочерних процесса:
    - **Процесс 1 (для `ls -l`):** закрывает `r_fd`, `dup2`ет `w_fd` на `1` (stdout), затем `exec`ает `ls -l`.
    - **Процесс 2 (для `less`):** закрывает `w_fd`, `dup2`ет `r_fd` на `0` (stdin), затем `exec`ает `less`.
3. Данные, которые `ls -l` пишет в свой `stdout`, автоматически считываются `less` из его `stdin`.

```
           +-----------+         +-----------+
 ls -l ---+           |  pipe   |           |---> less
          +---write---+----------+---read----+
             (stdout)    (kernel)   (stdin)
```

`pipe2` – это улучшенная версия `pipe`, которая позволяет указать дополнительные флаги, например `O_CLOEXEC`, чтобы файловый дескриптор автоматически закрывался при вызове `exec`.

### Системный вызов `stat`

`stat` – это системный вызов, который возвращает подробную информацию (метаданные) о файле. Он не читает содержимое файла, а обращается к `inode`.

Прототипы вызовов:

```c
#include <sys/stat.h>

int stat(const char *pathname, struct stat *buf);
int fstat(int filedes, struct stat *buf);
int lstat(const char *pathname, struct stat *buf);
```

- `stat`: возвращает информацию о файле по его пути. Если путь ведёт к симлинку, `stat` **следует** по нему и возвращает данные о конечном файле.
- `fstat`: возвращает информацию об уже открытом файле по его файловому дескриптору (`filedes`).
- `lstat`: как и `stat`, работает с путём, но **не следует** по симлинку, а возвращает данные о самой символической ссылке.

Второй аргумент `buf` - это указатель на структуру `struct stat`, куда и записывается вся информация. Эта структура содержит множество полей, самые важные из которых:

- `st_mode`: тип файла и права доступа.
- `st_ino`: номер `inode` файла.
- `st_size`: размер файла в байтах.
- `st_dev`: идентификатор устройства, на котором находится файл.
- `st_uid`: идентификатор пользователя (UID) - владельца файла.
- `st_gid`: идентификатор группы (GID) - владельца файла.
- `st_atime`: время последнего доступа к файлу.
- `st_mtime`: время последнего изменения содержимого файла.
- `st_ctime`: время последнего изменения метаданных файла (например, прав доступа).

#### Пример из семинара (`stat.c`)

Эта программа использует `stat` (или `lstat`) для вывода метаданных файла, переданного в качестве аргумента.

```c
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/types.h>

int main(int argc, char **argv) {
    if(argc < 2) {
        fprintf(stderr, "filename is required\\n");
        exit(1);
    }

    struct stat file_stat;
    // lstat используется, чтобы не разыменовывать симлинки
    if (lstat(argv[1], &file_stat) < 0) {
        perror(argv[1]);
        exit(1);
    }

    printf("Size of file: %lu bytes\\n", file_stat.st_size);
    printf("File inode: %lu\\n", file_stat.st_ino);
    printf("Is file symlink: %s\\n", S_ISLNK(file_stat.st_mode) ? "yes" : "no");
    
    // Проверяем права доступа пользователя
    printf("User permissions: ");
    if (file_stat.st_mode & S_IRUSR) {
        printf("r");
    } else {
        printf("-");
    }
    if (file_stat.st_mode & S_IWUSR) {
        printf("w");
    } else {
        printf("-");
    }
    if (file_stat.st_mode & S_IXUSR) {
        printf("x");
    } else {
        printf("-");
    }
    printf("\\n");
    
    // Выводим UID и GID
    printf("User ID (UID): %lu\\n", (unsigned long)file_stat.st_uid);
    printf("Group ID (GID): %lu\\n", (unsigned long)file_stat.st_gid);

    return 0;
}
```

Чтобы проверить права доступа, мы используем **битовые операции**. Например, `file_stat.st_mode & S_IRUSR` проверяет, установлен ли бит чтения для владельца файла. `S_IRUSR`, `S_IWUSR` и `S_IXUSR` - это константы, которые определяют соответствующие биты.

### Специальные биты: SUID, SGID и Sticky Bit

Эти биты можно установить с помощью `chmod`. Они имеют особые функции:

- **SUID (Set User ID):** Если этот бит установлен для исполняемого файла, то программа будет выполняться с правами владельца этого файла, а не с правами пользователя, который её запустил.
    - **Пример:** У `passwd` установлен SUID. Когда ты запускаешь `passwd`, она временно получает права суперпользователя (root), чтобы изменить `/etc/shadow`.
- **SGID (Set Group ID):**
    - **Для файлов:** Аналогично SUID, программа запускается с правами группы-владельца файла.
    - **Для директорий:** Все новые файлы, созданные в этой директории, будут наследовать группу этой директории, а не группу создателя. Это удобно для совместной работы над проектами.
- **Sticky Bit:** Устанавливается только для директорий. Если он установлен, то только владелец файла или директории может удалить или переименовать файл внутри неё, даже если у других пользователей есть права на запись (`w`) в эту директорию.
    - **Пример:** `chmod 1777 /tmp`. Это предотвращает удаление чужих файлов в общей директории `/tmp`.

> [!warning]
> Про какой-то из этих специальных битов (не помню какой точно) спросят на следующей летучке!

### Системный вызов `lseek`

`lseek` используется для **изменения позиции** в файле. Каждый открытый файл имеет **текущую позицию** (file pointer), с которой начинается чтение или запись. `lseek` позволяет переместить этот указатель.

Прототип вызова: `off_t lseek(int fd, off_t offset, int whence);`

- `fd`: файловый дескриптор.
- `offset`: смещение, на которое нужно переместиться.
- `whence`: откуда начинать смещение:
    - `SEEK_SET`: от начала файла.
    - `SEEK_CUR`: от текущей позиции.
    - `SEEK_END`: от конца файла.

**Материалы с семинара:**

1. **Создание бинарного файла:** `python3 bins.py`

```python
# assuming you want 4-byte (32-bit) unsigned integers
# endian

with open('file.bin', 'wb') as f:
    f.write((1).to_bytes(4, 'little'))
    f.write((2).to_bytes(4, 'little'))
    f.write((10000).to_bytes(4, 'little'))
```

Этот скрипт создаёт файл `file.bin` с тремя 4-байтовыми числами: 1, 2 и 10000. В Little-endian формате они будут выглядеть так: `01 00 00 00`, `02 00 00 00`, `10 27 00 00`.
    
2. **Чтение файла:** `read_bin.elf file.bin` Эта программа читает файл и выводит числа: `1`, `2`, `10000`.

```c
#include <assert.h>
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>

int main(int argc, char* argv[]) {
    // argv[0] = "./a.out"
    if (argc < 2) {
        fprintf(stderr, "expected filename\n");
        exit(1);
    }
    int fd = open(argv[1], O_RDONLY);
    if (fd < 0) {
        perror("Failed to open file");
        return 1;
    }


    unsigned res = 0;
    ssize_t bytes_read;
    while ((bytes_read = read(fd, &res, sizeof(unsigned))) > 0) {
        printf("%u\n", res);
    }

    close(fd);

    return 0;
}

```
    
3. **Использование `hexdump`:** `hexdump file.bin` Вы увидите шестнадцатеричное представление содержимого файла: `0000000 0100 0000 0200 0000` `0000008 1027 0000`
    
4. **`lseek` для чтения определённого байта:** 

```c
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <unistd.h>


int main(int argc, char* argv[]) {
    int file = open(argv[1], O_RDONLY);  // хотим уметь только читать

    if (file == -1) {
        perror("lala");  // более осмысленная ошибка
        exit(1);
    }

    long offset;
    sscanf(argv[2], "%ld", &offset);

    // выставляет file pointer в нужное место
    if (lseek(file, offset, SEEK_SET) == -1) {
        perror("lseek");
        exit(1);
    }

    char c;
    if (read(file, &c, sizeof(char)) == -1) {
        perror("read");
        exit(1);
    }

    printf("%x\n", c);

    close(file);
    return 0;
}
```

`lseek.elf file.bin 1` Эта программа перемещает указатель на 1 байт от начала файла (`SEEK_SET`) и читает один байт. Результатом будет `00`, так как это второй байт в числе `1` (`01 00 00 00`).
