# Конспект

## 1. Основы ASM (Assembly)

Ассемблер - это низкоуровневый язык программирования, представляющий собой человекочитаемое отображение машинных инструкций процессора.

Файлы ассемблера обычно имеют расширение `.S` (если в них есть макросы препроцессора) или `.s` (если их нет).

```asm
    .global main
main:
    call readi32     // считали первое число
    movl %eax, %ecx  // сохранили его в ecx
    call readi32     // считали второе число в eax
    addl %ecx, %eax  // сложили первое и второе
    call writei32    // вывели результат
    call finish      // завершили программу
```

### Принцип архитектуры Фон Неймана

Согласно модели Фон Неймана, программа и данные хранятся в одной памяти. Это означает, что ошибка при записи данных может привести к перезаписи кода.

**Пример:**

```c
char s[200];
scanf("%s", s); // Потенциальная ошибка: переполнение буфера
```

Эта уязвимость известна как _stack smashing_ - переполнение стека, позволяющее злоумышленнику изменить адрес возврата.

## 2. Работа с tmux и GDB

### Tmux (Terminal Multiplexer)

**Tmux** - это инструмент, позволяющий управлять несколькими терминалами в одном окне. Особенно полезен при разработке клиент-серверных приложений.

**Установка:**

```bash
apt install tmux
```

**Основные команды:**

```bash
tmux new -s session      # создать новую сессию
tmux ls                  # список сессий
tmux attach -t session   # подключиться к сессии
```

**Горячие клавиши (после префикса `Ctrl + B`):**

- `c` - новое окно
- `0–9` - выбор окна
- `&` - закрыть текущее окно
- `l` - перейти к предыдущему окну
- `n` - следующее окно
- `d` - отсоединить клиент
- `"` - разделить панель по горизонтали
- `%` - разделить панель по вертикали
- `←/→/↑/↓` - перемещение между панелями
- `[` - режим прокрутки, `q` - выход из него

### Отладка в GDB

**GDB (GNU Debugger)** позволяет анализировать выполнение программы на уровне инструкций.

**Пример использования:**

```bash
gdb hello.elf
b main        # установить точку останова
run           # запустить
p/x $eax      # вывести значение регистра в шестнадцатеричном формате
p/d $ebx      # вывести значение регистра в десятичном формате
info b        # показать все брейкпоинты
```

**ASM разбор с помощью objdump:**

```bash
objdump -fhd sum > sum.dump
```

**GDB TUI (Text User Interface):**

```bash
tui layout src        # исходный код
tui layout asm        # ассемблерный код
tui layout regs       # регистры
```

**Переключение окон:** `Ctrl + X, затем O`

## 3. Линейный алгоритм, ветвление и цикл в ASM

### Безусловный переход

```asm
jmp label   ; перейти без условий
```

### Условные переходы (на основе флагов)

- `e` - equal (равно)
- `n` - not (не)
- `g` - greater (знаковые)
- `l` - less (знаковые)
- `a` - above (беззнаковые)
- `b` - below (беззнаковые)

Примеры команд:

- `je`, `jne` - равно / не равно
- `jg`, `jge`, `jl`, `jle` - сравнение со знаком
- `ja`, `jae`, `jb`, `jbe` - сравнение без знака

**Таблица переходов:**

|Условие|Флаг|Интерпретация|
|---|---|---|
|`jz`|ZF = 1|результат равен 0|
|`js`|SF = 1|результат отрицательный|
|`jc`|CF = 1|произошёл перенос|
|`jo`|OF = 1|переполнение знакового числа|

**Примеры эквивалентов C-кода:**

```asm
cmp $0, %eax
jle l1
{ code1 }
jmp l2
l1:
{ code2 }
l2:
```

Соответствует:

```c
if (eax > 0) {
    code1;
} else {
    code2;
}
```

## 4. Работа с регистрами и памятью

### Системные регистры

Регистр **EFLAGS** хранит флаги, отражающие результаты последних операций.

**Основные флаги:**

- **CF** (Carry Flag) - перенос при сложении/вычитании беззнаковых чисел
- **OF** (Overflow Flag) - переполнение для знаковых чисел    
- **ZF** (Zero Flag) - результат равен нулю
- **SF** (Sign Flag) - отрицательный результат

Проверка флагов в GDB:

```bash
p $eflags
```

## 5. Знаковые и беззнаковые числа. Дополняющий код

### Представление чисел

- **Беззнаковое** (`unsigned`) - обычное двоичное представление.
- **Знаковое** (`signed`) - используется **дополняющий код (two’s complement)**.

Для отрицательных чисел старший бит (MSB) равен 1. Значение вычисляется как `−(2ⁿ − значение)`.

**Пример:**

```
mov $0xFF, ah
```

Если рассматривать `ah` как беззнаковое: `255`. Если как знаковое: `-1`.

Проверка в GDB:

```bash
p/d $ah   # интерпретация как знаковое число
p/u $ah   # интерпретация как беззнаковое число
```

## 6. Сдвиги и битовые операции

- `shl` (shift left) - сдвиг влево (умножение на 2)
- `shr` (shift right) - сдвиг вправо (деление на 2 без знака)
- `sar` (shift arithmetic right) - арифметический сдвиг вправо (с сохранением знака)

## 7. Стек и CPU

**Стек (stack)** - область памяти, используемая для хранения локальных переменных и адресов возврата.

### Соглашение о сохранении регистров

Некоторые регистры должны сохраняться при вызове функции (_callee-saved_):

```
rbx, rsp, rbp, r12–r15
```

### Пример цикла в ASM

```asm
movl $10, %eax
l:
    {code}
    dec %eax
    cmp $0, %eax
    jne l
```

Соответствует циклу `while` в C:

```c
int eax = 10;
while (eax != 0) {
    code;
    eax--;
}
```

## 8. readi64 и writei64

Функции для взаимодействия с вводом-выводом 64-битных целых чисел в ассемблерных программах.

```asm
call readi64   ; чтение числа в регистр
call writei64  ; вывод числа на экран
```

Обычно реализуются через системные вызовы (syscalls) или функции стандартной библиотеки.

## 9. Отличие синтаксисов Intel и AT&T

Ассемблер GNU (используемый в Linux) по умолчанию использует синтаксис **AT&T**, но можно переключиться на **Intel**, добавив директиву:

```asm
.intel_syntax noprefix
```

### Отличия:

- **Порядок операндов**:
    - AT&T: `instr src, dest`
    - Intel: `instr dest, src`
        
- **Регистры**:
    - AT&T: `%rax`, `%rbx`
    - Intel: `rax`, `rbx`
        
- **Константы**:
    - AT&T: `$5`
    - Intel: `5`
        
- **Память**:
    - AT&T: `mov %eax, (%rbx)`
    - Intel: `mov eax, [rbx]`
        
- **Переключение синтаксиса**:
    - `.att_syntax prefix` - вернуть обратно в AT&T.

## 10. Примеры кода

### Пример 1: `sb`

```asm
.intel_syntax noprefix
.global main
main:
    call readi64
    mov  rbx, 2
    and  rax, rbx
    shr  rax, 1
    mov  rdi, rax
    call writei64
    call finish
```

---

### Пример 2: `us`

```asm
.intel_syntax noprefix
.global main
main:
    mov ah, 0xff
    shr ah, 2
    mov ah, 0xff
    sar ah, 2
    call finish

.intel_syntax noprefix
.global main
main:
    xor rbx, rbx
loop:
    add rbx, 1
    mov rdi, rbx
    call writei64
    mov rcx, rbx
    sub rcx, 20
    jl loop
    call finish
```

---

### Пример 3: `loop`

```asm
.intel_syntax noprefix
.global main
main:
    xor rax, rax
loop:
    call readi64
    mov rbx, rax
    mov rcx, 10
    sub rbx, rcx
    jz done
    jmp loop
done:
    call finish
```

---

### Пример 4: `loop_if`

```asm
.intel_syntax noprefix
.global main
main:
    call readi64
    mov rbx, rax
    call readi64
    mov rdi, rax
    cmp rdi, rbx
    jge label
    mov rdi, rbx
label:
    call writei64
    call finish
```

---

### Пример 5: `alg1`

```asm
.intel_syntax noprefix
.global main
main:
    call readi64
    mov r12, rax
    call readi64
    mov r13, rax
```

### Пример 6: `alg2`

```asm
l1:
    cmp r13, r12
    je l3
    ja l2
    xchg r13, r12
l2:
    sub r13, r12
    jmp l1
l3:
    mov rdi, r12
    call writei64
    call finish
```

## 11. Локальное тестирование ассемблерных программ

1. Создайте файл `main.S` с кодом.
2. Убедитесь, что рядом есть файл `simpleio_x86_64.S` (содержит реализацию `readi64`, `writei64`, `finish` и др.).
3. Скомпилируйте и выполните:
    
    ```bash
    gcc -g main.S simpleio_x86_64.S -o main
    ./main
    ```
    
4. Для дизассемблирования:
    
    ```bash
    objdump -fhd main > main.dump
    ```

## 12. Makefile

Makefile позволяет удобно собирать, чистить и анализировать программы.

Пример общего Makefile для ассемблера:

```makefile
build: alg1

clean:
	rm -rf alg1

alg1: alg1.S
	gcc -g alg1.S simpleio_x86_64.S -o alg1

dump: alg1
	objdump -fhd alg1 > alg1.dump
```

### Как использовать

- `make` или `make build` - сборка программы.
- `make dump` - генерация дампа.
- `make clean` - очистка.

Можно расширить Makefile для нескольких файлов:

```makefile
TARGETS = alg1 alg2 loop loop_if sb us

all: $(TARGETS)

$(TARGETS): %: %.S
	gcc -g $< simpleio_x86_64.S -o $@

clean:
	rm -rf $(TARGETS)
```

Такой файл позволяет собрать все ассемблерные примеры одной командой:

```bash
make all
```
