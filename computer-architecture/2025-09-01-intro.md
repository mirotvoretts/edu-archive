# Системные вызовы и ASM

## Зачем нужна ОС?

### Работа с аппаратурой

- **Аппаратные устройства** (диск, клавиатура, сеть, экран) слишком сложные для прямого использования.
- ОС предоставляет **драйверы** - функции, которые скрывают детали работы железа и дают удобный интерфейс.

Современные процессоры (ARM, x86) имеют **уровни привилегий**:

- **User mode** (`user`)- обычные программы, сильно ограниченные в правах.
- **Kernel mode** (`priv`)- ядро ОС и драйверы, могут напрямую работать с аппаратурой.

**Системный вызов (syscall)** = переключение процессора из `user` в `kernel`.

```
[User program] --syscall--> [Kernel (ОС)] --ret--> [User program]
```

> **Регистр** - это сверхбыстрая внутренняя память процессора. Размер одного регистра 64 бита (пример: `ax`, `bx`, `cx`, ... допустим их 10 штук). Используются для арифметики, хранения промежуточных данных, адресации памяти

```
CPU Registers (~1ns)
   ↓
Cache L1 (~2-4ns)
   ↓
Cache L2 (~10ns)
   ↓
Cache L3 (~30ns)
   ↓
DRAM (~100ns)
   ↓
SSD (~50-100 мкс)
   ↓
HDD (~5-10 мс)
```

> **POSIX** (Portable Operating System Interface) - набор стандартов для системного API, библиотек языка C, интерфейсов приложений.
> 
> Главная цель - **совместимость UNIX-систем** и переносимость программ.

### Многозадачность

Многозадачности "по-настоящему" нет.  
**Один процессор выполняет только одну инструкцию в данный момент времени.**

ОС делает **быстрое переключение контекста** между процессами:

1. Таймер (например, 30мс) вызывает прерывание.
2. ОС сохраняет состояние текущего процесса (регистры, счётчик инструкций).
3. Загружает состояние другого процесса.

**Планировщик** хранит список программ, которые мы хотим выполнить по порядку. Именно он настраивает таймер на каждые 30мс

- **Квант** = минимальное время, выделяемое процессу.
- В Linux обычно 10–100мс.
- Если квант слишком мал -> система тратит время на переключения.
- Если квант слишком велик -> процессы "висят" в очереди, система менее отзывчива.

```
Time ---->
| P1 | P2 | P3 | P1 | P2 | ...
 ^^^
 Квант (time slice, ~30мс)
```

#### Пример программы на ASM

```asm
"a = b + c"  -->  load ax 0x10
                  load bx, 0x20
                  add cx, ax, bx
                  store cx, 0x30
```

- Процессор смотрит: есть ли `b` и `c` в регистрах.
- Если нет -> ищет в кэше L1.
- Если нет -> идёт в L2.
- Если нет -> идёт в L3.
- Если нигде нет -> идёт в DRAM (долго).
- Результат хранит в регистре (самое быстрое место).

### Изоляция программ друг от друга

Если бы программам дать доступ к одной памяти -> они бы мешали друг другу

**Решение:** виртуальная память
Каждый процесс думает, что у него "своя память"

```
PRG1                PRG2
store ax, 0x1000    load ax, 0x1000
```

| PID (номер программы) | VA (виртуальный) | PA (физический) |
| --------------------- | ---------------- | --------------- |
| 1                     | 0x1000           | 0x1000000       |
| 2                     | 0x1000           | 0x3000          |

```
[CPU] --вирт.адр--> [MMU] --физ.адр--> [DRAM]
```

```
        +-------------+
        |  ПРОЦЕССОР  |
        |-------------|
        | Регистры    | ~1 такт
        | Кэш L1      | 2-4 такта
        | Кэш L2      | ~10 тактов
        | Кэш L3      | 30-40 тактов
        +------^------+
               |
         [Системная шина]
               |
   +-----------+-----------+
   |                       |
+------+               +-------------+
| DRAM |               | Устройства  |
|(RAM) |               | (диск, сеть,|
|100нс |               | экран и т.д)|
+------+               +-------------+

```

> **Шина** - это набор проводников + протоколов, соединяющий компоненты компьютера.
> Передаёт **данные**, **адреса** и **сигналы управления** между процессором, памятью и устройствами.
> Условно: это как «дороги», по которым бегают данные.

В компьютерных шинах используется принцип "рукопожатия":
- Отправитель говорит: «Данные готовы»
- Получатель отвечает: «Принял»

```
CPU ---> [Req] ---> Device
CPU <--- [Ack] <--- Device
```

>**DRAM (Dynamic Random Access Memory)** - это основная оперативная память компьютера.
>Хранит данные и программы, которые сейчас работают.
>Нуждается в постоянном обновлении (refresh), иначе теряет данные.
>Большая по объёму (гигабайты), но медленнее кэша и регистров.
>Пример: когда запускаешь браузер, его код и вкладки лежат в DRAM.

> **Кэш** - это маленькая сверхбыстрая память внутри самого процессора
> Нужна, чтобы ускорять доступ к часто используемым данным и инструкциям.
> Иерархия кэшей:
> 	L1 - самый маленький (десятки килобайт), но очень быстрый
> 	L2 - больше (сотни килобайт), чуть медленнее
> 	L3 - ещё больше (несколько мегабайт), самый медленный из кэшей

```
[Процессор] ←→ [Кэш внутри процессора]
                 ↓
                 ↓ через системную шину
                 ↓
             [Оперативная память (DRAM)]
```

> [!warning] 
>  **Регистры и кэши (L1–L3)** находятся **внутри процессора**.
>  **DRAM (оперативка)** - отдельные микросхемы на материнской плате.
>  **Системная шина** соединяет процессор, память и устройства.

# Linux

Мы ввели команду `ls`, например, в терминал Linux, кто сделал системый вызов, почему мы получили вывод? Ответ - **командый интерпретатор**, самый популярный - **Bash**

```bash
ls -la
```

1. **Shell (Bash)** принимает команду
2. Shell вызывает **системный вызов `execve("ls", ...)`**
3. ОС загружает программу `/bin/ls`
4. Программа `ls` вызывает системные вызовы (`open`, `read`, `write`) -> выводит результат в терминал
